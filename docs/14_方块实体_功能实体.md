# 方块实体类 —— 功能逻辑

代码位置：`blockentity/` 包、`registry/ModBlockEntities.java`。

## 1. KnappingTableBlockEntity（敲石台）
- **NBT 数据**：`Grid`（32×32 打制网格，每格 1 bit 共 128 字节）、`InitialFilled` / `StrikeCount`（打制度统计）、`Stone`（放置的原石 + 五维隐藏属性）、`ActiveTool`（吸附中的工具）、`Items`（5 格打制工具槽）
- **五维隐藏属性**（`smod:stone_properties`，不显示）：
  | 维度 | 影响 |
  |---|---|
  | 岩性成分 | 基础可打性上限（成品锋利度 = 打制性能 × (0.5 + 岩性/200)） |
  | 成岩与风化 | 中/重度无法打制；轻度降低成品基础耐久 |
  | 力学与断裂 | 每次打击掷骰：崩边（随机边缘剥落 4~8 格）/ 炸裂（整块报废） |
  | 打制性能 | 成品锋利度主来源 |
  | 缺陷与结构 | 网格外围 3 层随机缺失（越外侧越易缺失，禁止封闭孔洞）+ 降低基础耐久 |
- **成品四维**（`smod:stone_tool` 石质工具组件 + 逐件 `MAX_DAMAGE`）：
  - 打制度 = 缺失方格比例；锋利度 = 打制性能 × 岩性上限系数
  - 尖锐度 = 左、右、上三面轮廓峰值检测（凸尖落差总和归一化）
  - 耐久度 = 风化/缺陷定基础（40~100 分），三项正面属性合计最多削弱 15%，换算为 155~267 耐久
- **同步**：`syncToClient()` 经 BE update tag 推送网格与槽位；C2S 包（吸附/放下/敲击/取出）服务端权威校验
- **Tick**：无每帧逻辑（纯交互型）

## 2. FirePitBlockEntity（篝火坑）
- **NBT 数据**：`Items`（燃料/引火物/待加热 三槽）、`FuelTime`（剩余燃烧 tick）、`CookProgress`
- **逻辑**：
  - `tryIgnite(chance)`：需引火物，按概率点燃，设定初始燃烧时间
  - `serverTick`：FuelTime-- ；耗尽时尝试续燃（槽 0），否则熄灭（LIT=false）
  - 烹饪：加热槽（槽 2）有可烹饪物且点燃状态，每 400 tick 转换
- **烹饪表**：生牛肉/猪排/鸡肉/鳕鱼/鲑鱼/羊肉 → 对应熟食；土豆 → 烤土豆
- **实现**：`NonNullList<ItemStack>` + `ContainerHelper` 序列化；`Containers.dropContents` 掉落

## 3. DryingRackBlockEntity（晾晒架）
- **NBT 数据**：`Hanging`（悬挂物）、`DryingProgress`
- **逻辑**：`level.isDay()` && `level.canSeeSky(pos.above())` → progress+1，满 24000 tick 转换产物
- **转换表**：
  | 输入 | 输出 |
  |---|---|
  | 生肉（牛/猪/鸡/鳕鱼/鲑鱼/羊） | 肉干 |
  | 湿陶坯 | 干陶坯 |
  | 植物纤维 | 干燥纤维 |

## 4. PitKilnBlockEntity（土窑）
- **NBT 数据**：`Items`（燃料/输入/输出 三槽）、`BurnTime`、`Progress`
- **逻辑**：
  - 燃料映射：树皮 800t / 树脂 1200t / 干燥纤维 400t / 其他复用 NeoForge `CommonHooks.getBurnTime`
  - 烧制映射：湿陶坯 → 陶罐；干陶坯 → 陶罐
  - 骨架版烧制时长 1200t（正式版 12000t）
  - 失败处理：中途被破坏 → 未完成陶坯按原状态掉落（对齐原版"进度丢失"原则）

## 5. WickerBasketBlockEntity（简易储物篮）
- **NBT 数据**：`Items`（9 格）
- **逻辑**：纯容器；被破坏时内容物一并掉落

## 通用约定
- 注册：`DeferredRegister.create(Registries.BLOCK_ENTITY_TYPE, MODID)`
- 序列化：`saveAdditional(CompoundTag, HolderLookup.Provider)` / `loadAdditional(CompoundTag, HolderLookup.Provider)`
- 每 tick 逻辑仅 `!level.isClientSide` 时执行
- 容器类后续实现 `WorldlyContainer` 以兼容原版漏斗（电气时期自动化预留）
